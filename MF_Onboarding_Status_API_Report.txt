MF Onboarding Status API — Implementation Report
=================================================

Status: COMPLETE — All requirements met


ENDPOINT
--------
GET /api/v1/customer/onboarding/status

Registered in main.py under the customer router.
Authentication: require_sso_auth (SSO cookie + Bearer fallback).


REQUIREMENTS VS IMPLEMENTATION
-------------------------------

Requirement                          Status    Notes
----------------------------------------------------------------------------------------------------
All 6 steps checked in one request   DONE      asyncio.gather runs all 6 in parallel
Per-step error isolation             DONE      Each _check_* catches all exceptions,
                                               returns done=false, status="check_failed"
60s per-user cache                   DONE      _onboarding_cache dict keyed by lendrix_uuid,
                                               TTL via time.monotonic()
SSO cookie auth                      DONE      require_sso_auth dependency
                                               (also accepts Bearer token fallback)
onboarding_complete = all 6 done     DONE      all(s["done"] for s in steps.values())
Response shape matches spec          DONE      Exact field names and structure


STEP-BY-STEP LOGIC
------------------

Step       API Called                  done = true when
------------------------------------------------------------------------------------------
UCC        DB (sso_payload)            client_codes list is non-empty
eKYC       CLIENT_KYC_REPORT           kyc_status == "SUCCESS"
                                       AND "KYC VALIDATED" in status_remark
AOF        AOF_IMAGE_UPLOAD_REPORT     Any record where cams_status or kfin_status
                                       contains "ready to invest", "uploaded", or "success"
eLog       ELOG_UPLOAD_REPORT          Same success keyword check as AOF
Mandate    MANDATE_STATUS              Any record with status in {approved, active}
Nominees   client_master_report        Any nominee_1/2/3_name non-empty across records

EDGE CASE — NO CLIENT CODE
--------------------------
If the user has no client_code yet (UCC not done), steps eKYC, AOF, eLog,
Mandate, and Nominees all return immediately without hitting NSE:

  { "done": false, "status": "no_client_code", ... }

This is correct behaviour — all those steps require a client code.
